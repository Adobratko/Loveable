# TIPPS FÜR FEATURES

Dieses Dokument hilft dir, bessere und klarere Features zu bauen.

👉 Ziel:
- keine Feature-Explosion
- klare App-Struktur
- saubere Grundlage für Loveable

---

## 1. START IMMER MIT DER KERNFUNKTION

Bevor du Features definierst, frage dich:

👉 Was ist die EINE Hauptaktion im Produkt?

Beispiele:
- Aufgaben erstellen
- Leads verwalten
- Content generieren

Alles andere baut darauf auf.

---

## 2. FEATURES SIND NUR UNTERSTÜTZUNG

Features sind NICHT das Produkt.

Sie helfen nur der Kernfunktion.

❌ falsch:
- 10 verschiedene Hauptfunktionen

✔ richtig:
- 1 Hauptfunktion + unterstützende Features

---

## 3. MAXIMAL 3–5 HAUPTFEATURES

Mehr ist fast immer zu viel.

Regel:
👉 Wenn du mehr als 5 brauchst, ist das Produkt zu kompliziert gedacht.

---

## 4. USER FLOW IST WICHTIGER ALS FEATURES

Frage immer:

👉 Wie bewegt sich der Nutzer durch das Produkt?

Wenn der Flow nicht klar ist → Features sind falsch geplant.

---

## 5. DENKE IN SCHRITTEN, NICHT FUNKTIONEN

User Flow Beispiel:

1. Nutzer kommt rein  
2. Nutzer macht Input  
3. System verarbeitet  
4. Ergebnis entsteht  

👉 daraus entstehen Features automatisch

---

## 6. SUPPORT FEATURES SIND NUR HILFE

Support Features dürfen NICHT zentral sein.

Beispiele:
- Suche
- Filter
- Erinnerungen
- History

---

## 7. PRIORITÄT IST EXTREM WICHTIG

Immer sortieren:

- MUST HAVE → ohne geht nichts
- SHOULD HAVE → wichtig, aber nicht kritisch
- NICE TO HAVE → optional

👉 alles andere ist später Chaos

---

## 8. FEATURES SOLLEN DIE KERNFUNKTION VERSTÄRKEN

Wenn ein Feature nichts zur Kernfunktion beiträgt:

👉 löschen

---

## 9. KEIN FEATURE DENKEN OHNE PROBLEM

Fehler:
❌ „Was könnte man noch einbauen?“

Richtig:
✔ „Braucht der Nutzer das wirklich, um sein Problem zu lösen?“

---

## 10. WENIGER FEATURES = BESSERE APP

Ein starkes Produkt ist immer fokussiert.

👉 Einfachheit schlägt Komplexität

---

## 🧠 MINI CHECKLISTE

Bevor du fertig bist:

✔ 1 Kernfunktion klar  
✔ max. 3–5 Hauptfeatures  
✔ User Flow verständlich  
✔ keine unnötigen Features  
✔ alles löst das Hauptproblem  

---

## 🎯 ZIEL DIESES DOKUMENTS

Du sollst damit:

- bessere Feature Entscheidungen treffen
- unnötige Komplexität vermeiden
- saubere Inputs für Loveable erstellen
