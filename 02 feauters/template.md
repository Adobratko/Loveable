# FEATURES TEMPLATE

Dieses Template hilft dir, aus einer Produktlogik echte Features zu bauen.

👉 Wichtig:
- Produktlogik zuerst fertig machen
- dann erst Features definieren
- nicht zu viele Features bauen

---

## 1. PRODUKTNAME
Für welches Produkt werden die Features gebaut?

---

## 2. KERNPROBLEM (KURZ)
Was ist das Hauptproblem des Nutzers?

👉 nur 1 Satz

---

## 3. KERNFUNKTION (HAUPTAKTION)
Was ist die wichtigste Aktion im Produkt?

Beispiel:
- Aufgaben erstellen
- Leads verwalten
- Inhalte generieren

---

## 4. HAUPTFEATURES

Liste die wichtigsten Funktionen, die das Produkt braucht.

👉 max. 3–5 Features

Frage:
- Was braucht der Nutzer wirklich, um die Hauptfunktion zu nutzen?

---

## 5. SUPPORT FEATURES

Welche zusätzlichen Funktionen helfen dem Hauptfeature?

Beispiele:
- Filter
- Suche
- Benachrichtigungen
- Export

👉 nur unterstützend, nicht zentral

---

## 6. USER FLOW (EINFACH)

Beschreibe den Ablauf vom Nutzer:

1. Nutzer kommt ins System
2. Nutzer macht X
3. System reagiert mit Y
4. Ergebnis entsteht

👉 einfach in Schritten denken

---

## 7. FEATURE PRIORITÄT

Ordne die Features nach Wichtigkeit:

- MUST HAVE (muss existieren)
- SHOULD HAVE (wichtig, aber nicht kritisch)
- NICE TO HAVE (optional)

---

## 8. FEATURE GRENZEN

Was gehört NICHT ins Produkt?

👉 wichtig, damit Features nicht explodieren

Beispiele:
- kein Chat System
- kein Social Network
- kein komplexes ERP

---

## 🧠 MINI CHECK

Bevor du fertig bist:

✔ nur 1 Kernfunktion unterstützt  
✔ max. 3–5 Hauptfeatures  
✔ User Flow ist klar  
✔ keine Feature-Explosion  
✔ alles unterstützt das Hauptproblem  

---

## 🎯 ZIEL DIESES TEMPLATES

Am Ende hast du:

- klare Features
- einfache Struktur
- sauberen User Flow
- Grundlage für Loveable Implementation
